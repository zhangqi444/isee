# Sheila ISEE — practice site

A React app built on **shadcn/ui** (Tailwind v4 + Radix primitives, components
copied into `src/components/ui/` the way shadcn intends) with a Vite build. It
shadows the Google Sheets question banks, keeps progress in the browser, and —
once the learner authorizes it — mirrors that progress to a JSON file in a folder
it creates in her own Google Drive.

Live at https://learning.sheilazhang.org/ (GitHub Pages, custom domain).

## Layout

    index.html              Vite entry
    vite.config.js          two targets, see below; `@` → src/
    src/main.jsx            boot: load the bank, apply the Sheets migration seed, theme, render
    src/App.jsx             shell (sidebar + header, shadcn dashboard layout) and the hash router
    src/lib/store.js        progress store: localStorage + Google Drive (drive.file scope)
    src/lib/content.js      question-bank helpers (sets, progress, review pool, chart data)
    src/lib/router.js       tiny hash router — works under /learning/ and inside the artifact
    src/components/ui/      shadcn/ui components (button, card, sidebar, sheet, chart, …)
    src/components/         app-sidebar, site-header (breadcrumbs = always a way out), nav-user
    src/pages/              home (dashboard), subject (weeks + sets), runner, review,
                            precision (VR Session 1), essay (weekly workspace + guide),
                            mock (timed, sectioned forms), calendar (plan + ISEE dates)
    public/                 manifest, service worker, favicon
    content/bundle.json     834 practice questions, 4 mock forms (508 q), 36 passages, the
                            VR precision-review words, the essay programme and the calendar —
                            generated by make_bundle.py from ../content/
    content/seed.json       Sheila's Week-1 Sheets results (sets + precision responses),
                            generated by ../build_seed.py
    scripts/artifact.mjs    turns the single-file build into ../artifact.html
    test_e2e.cjs            Playwright end-to-end test against dist/ under /learning/
    test_features.cjs       essay, precision review, mock exams, calendar
    test_drive.cjs          Drive session cycle with Google stubbed
    test_artifact.cjs       smoke test of artifact.html inside a bare skeleton page

## Content sources

`../content/precision.json` (VR Session 1 words and tasks per week, joined with the
Vocabulary Master; words the master lacks were authored and independently checked),
`../content/essay.json` (weekly prompts, guide, rubric, prompt bank),
`../content/mock_essays.json` (the four unseen mock prompts) and
`../content/calendar.json` (researched ISEE seasons, formats, fees, Seattle-area
sittings and deadlines, each with a source URL) all feed `make_bundle.py`.

## Build

    npm ci
    npm run build            # → dist/           GitHub Pages: Drive sync on, bundle fetched
    npm run build:artifact   # → ../artifact.html claude.ai artifact: bundle inlined, no Drive
    npm test                 # needs Playwright + Chromium; run after `npm run build`

`vite.config.js` injects the OAuth client id (from `oauth.json`) and the Google
Identity script only into the Pages build. The artifact origin is not an
authorized OAuth origin, so that build has no Drive layer at all.

## Publishing on GitHub Pages

`.github/workflows/pages.yml` runs on every push to `main` that touches
`site/` or `content/`. It regenerates `content/bundle.json` from the question
banks and **fails if it differs from the committed one**, then `npm ci && npm run
build` and publishes `site/dist`. Pages "deploy from a branch" only offers the
repo root or `/docs`, which is why this uses the Actions source.

Every asset path is relative (`base: './'`), so the same build works at a domain
root, under `user.github.io/learning/`, and on the custom domain.

## Google Drive sync

Scope is `https://www.googleapis.com/auth/drive.file` — non-sensitive, so no
Google verification is needed, and the site can only ever see the folder and
file it created itself (`Sheila ISEE Practice/progress.json`). Merge is
last-write-wins per set by timestamp. If sign-in fails with *access_denied /
has not completed the Google verification process*, the OAuth consent screen
for the Cloud project is still in **Testing** mode: publish it to Production
(no verification required for this scope) or add the account as a test user.

## Sets

A week's questions are split into near-equal sets of at most 12 (37 → 10/9/9/9),
never a trailing set of one. `build_seed.py` uses the identical split so the
migrated Week-1 results line up with the sets on screen.

## Regenerating the question bank

`content/bundle.json` is generated from `../content/question-banks/*.json`, the
repo shadow of the Sheets workbooks. After the banks change:

    python3 site/make_bundle.py    # rebuilds bundle.json (folds in seed.json)
    cd site && npm run build
