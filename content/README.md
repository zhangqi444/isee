# content/ — shadow of the Google Sheets workbooks

Generated by `extract_content.py`; checked by `validate_content.py` (CI-ready, exits non-zero on any error).

`content/` is the canonical, versioned copy of every question the learner can see, exported from the Sheets workbooks **with the reviewed 2026-08-31 fixes already applied**. It is the seed content for the Drive-first PWA (spec §6.1) and the shadow of the live Sheets while those remain the authoring surface.

## Item shape

Every item carries the spec §6.1 fields: stable `id`, `schema_version`, `content_version`, `subject`, `skill`, `difficulty`, `prompt`, `choices` (A–D), `correct`, `explanation`, `misconceptions`, optional `passage_id`, `form`, `source`, and a deterministic `content_hash` (SHA-256 over the canonical record, hash excluded).

Attempts must reference the item **and** its `content_version`, so a completed session stays interpretable after content changes.

## Regenerating

```
python3 extract_content.py     # reads *.xlsx + fix manifests, writes content/
python3 validate_content.py    # 0 = clean
```

`extract_content.py` applies the fix manifests in memory before exporting, so re-running against unfixed workbook exports still yields corrected content. It never writes to the Sheets.

## What validation enforces

- no duplicate item IDs; every field present
- exactly four choices, none blank, none duplicated within an item
- `correct` is one of A–D; `passage_id` resolves to a real passage
- `content_hash` matches a recomputed digest
- **answer positions are not cyclic** — any bank/form/section above 60% predictable fails the build

That last check exists because the original workbooks were 100% predictable by position (Mock DIAGNOSTIC, MA and VR were perfect cycles or one rotated motif). It caught a regression during export — MOCK 3's VR section was still 68% after the first fix pass.

## Known gap

The 182 VR items have no `explanation` text — the VR answer key sheet never had an explanation column. They export with `explanation: ""` and are reported as warnings, not errors. Explanations should be authored before VR review can teach rather than just score.

## Answer keys are in this repo by design

Spec §3.2 lists prevention of source inspection as an explicit non-goal: a static client necessarily receives grading material, so answer-key concealment is a UX convention, not a security boundary. If the repository is public, note that this also makes the bank publicly *indexable* — a separate question from client-side exposure, and one worth deciding before the first deploy.
